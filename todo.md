# Todo

## Plan
Implement core features top-down starting with the Component class and registry (the main user-facing entry point), then build out template tags and slot system, followed by attribute handling, provide/inject, dependency management, and finally configuration/testing utilities.

## Tasks
- [x] Task 1: Implement the core Component class with template rendering and a component registry that supports register, unregister, get, has, all, and clear operations. Components should be definable as Python classes with inline template strings, and renderable via a static `render()` method that accepts kwargs and returns HTML. Include the `@register` decorator for convenient registration. Support `get_template_data()` for providing template context variables.
- [x] Task 2: Implement the template tag system with `{% component %}` / `{% endcomponent %}` tags that allow rendering registered components from Django templates, and basic `{% slot %}` / `{% endslot %}` and `{% fill %}` / `{% endfill %}` tags for content injection. Slots should support default/fallback content, and fills should replace slot content when provided.
- [x] Task 3: Implement advanced slot features including required slots that raise errors when not filled, a default slot flag for implicit content, scoped slots with data passing from slot to fill via a data variable, and slot fallback access from within fills.
- [x] Task 4: Implement HTML attribute formatting and merging utilities. The format function should convert a dict to an HTML attribute string, handling boolean attributes, None/False removal, and escaping. The merge function should combine multiple attribute dicts with special handling for class (Vue-like dict/list support with truthy filtering) and style (CSS property merging with None/False removal). Include an `{% html_attrs %}` template tag.
- [x] Task 5: Implement the provide/inject pattern with a `{% provide %}` template tag that makes named data available to all descendant components, and a `Component.inject()` method that retrieves provided data. The provided data should be accessible as an object with attributes corresponding to the keyword arguments passed to the provide tag.
- [x] Task 6: Implement JS/CSS dependency management with Script and Style classes, component Media inner class support, and `{% component_css_dependencies %}` / `{% component_js_dependencies %}` template tags that collect and render all component dependencies. Support both inline content and URL-based resources.
- [x] Task 7: Implement tag formatters that allow customizing how component template tags look. Include a default formatter using `{% component "name" %}{% endcomponent %}` syntax and a shorthand formatter using `{% name %}{% endname %}` syntax. Support using different formatters with different registries.
- [x] Task 8: Implement Django app configuration (AppConfig), application settings via a COMPONENTS dict in Django settings, template loader for component templates, and static file finders for component assets. Include context behavior setting supporting both "django" and "isolated" modes.
- [x] Task 9: Implement testing utilities including a `djc_test` decorator that manages component registry state between tests, supports parametrize for testing with different settings configurations, and ensures test isolation. Include a setup function for configuring Django settings in test environments.
- [>] Task 10: Implement programmatic component rendering features including render_to_response for creating Django HttpResponse objects, component self-referencing (accessing self.name, self.args, self.kwargs, self.slots within get_template_data), passing slots as Python objects to render(), and support for nested component rendering within templates.
